# ADR-0024 — Context-Aware Summaries via Map-Reduce

Status: Accepted

## Context

El `resume-agent` enviaba **toda** la conversación en un único prompt. Con
proveedores locales de ventana de contexto chica esto rompe: Ollama/llama.cpp
rechazan el pedido cuando el transcript supera el `num_ctx` del modelo
(`request (N tokens) exceeds the available context size (4096 tokens)`).

Se evaluaron dos caminos:

- **A — Elevar el contexto del servidor.** `KAOS_LLM_NUM_CTX` (ADR previo de
  esta serie) hace que KAOS envíe `num_ctx` por la API nativa `/api/chat` de
  **Ollama**, que **recarga** el modelo con esa ventana. Funciona con Ollama
  real, pero **no** con servidores OpenAI-compatibles tipo **Lemonade/llama.cpp**,
  que fijan el contexto **al cargar el modelo** e **ignoran** el parámetro por
  petición.
- **B — Trocear en el agente (map-reduce).** Dividir la conversación en trozos
  que entren en la ventana y sintetizar un único informe.

Una tentación temprana fue trocear **dentro del provider** y **concatenar** las
respuestas. Se descartó: para un resumen estructurado (`# Resumen Ejecutivo` /
`## Estado` / `## Decisiones` / `## Riesgos` / `## Próximos pasos`) concatenar
`resp1 + resp2` produce **dos medios informes** con encabezados duplicados y sin
correlación — degrada el conocimiento (viola *Knowledge before Reports*). El
troceo **depende de la semántica de la tarea**, que solo conoce el **Agent**, no
el provider (que solo cumple `complete(messages) -> str`).

## Decision

### A. Helper puro en el Core

Nace `kaos.core.chunking` (dato/función pura, sin imports de plugins):

- `estimate_tokens(text)` — heurística ~4 chars/token (sin tokenizer externo).
- `group_by_token_budget(items, size_of, budget)` — agrupa **preservando orden**
  para que cada grupo entre en `budget`.

Mantiene el Core *AI-Provider-Agnostic*: el agente lo usa a través del contrato
público `LLMProvider`.

### B. Map-Reduce en el `resume-agent`

`ResumeAgent` recibe un `context_tokens: int | None` opcional (la ventana del
modelo). Cuando está definido y el transcript **superaría** el presupuesto de
entrada:

1. **Map** — se agrupan los **eventos** (que el agente entiende) en trozos que
   entran en el presupuesto y cada trozo se condensa en **notas** en viñetas
   (prompt corto `MAP_PROMPT`).
2. **Reduce** — las notas se sintetizan en **UN** informe con el `SYSTEM_PROMPT`
   estructurado. Si las notas aún no entran, se condensan por grupos de forma
   **jerárquica** hasta converger.

El presupuesto de entrada se deriva de `context_tokens` menos el system prompt,
una reserva para la salida del modelo (`35 %`) y un margen de seguridad. Con
`context_tokens=None` se conserva el comportamiento **single-shot** (backward
compatible). La trazabilidad se mantiene: el artefacto sigue listando **todos**
los `source_events` y el `message_count` real.

### C. Semántica de `KAOS_LLM_NUM_CTX`

`context_tokens` se cablea desde `settings.llm_num_ctx` en la composición
(`build_llm`/`run_backfill`/`run_forum_backfill`/`run_github`). La variable pasa
a significar **"la ventana de contexto real del modelo, en tokens"**:

- **Ollama real:** subila (p. ej. 16384); KAOS eleva el contexto del servidor y
  el agente rara vez necesita trocear.
- **Lemonade/llama.cpp:** ponela en el valor **real** con que se cargó el modelo
  (p. ej. 4096). El agente **trocea** para caber; el `num_ctx` por petición es un
  no-op inofensivo en esos servidores.

`PROMPT_VERSION` sube a `3` y `prompt_signature` incorpora `context_tokens`, así
la cache recomputa cuando cambia la estrategia/ventana.

## Consequences

- Los resúmenes funcionan con **cualquier** proveedor, incluidas ventanas de
  contexto chicas y fijas (Lemonade/llama.cpp), sin degradar el formato.
- El troceo vive en la **capa correcta** (el Agent), usando el contrato público;
  el provider sigue siendo simple y agnóstico.
- Costo/latencia: una conversación grande implica **N+1** llamadas (N map + 1
  reduce, o más si hay reduce jerárquico). Aceptable frente a fallar o degradar.
- La estimación de tokens es aproximada; se puede afinar con `tiktoken` a futuro
  sin cambiar la interfaz.
- Base para llevar el mismo patrón a otros agentes (task-agent, chat-over-
  knowledge) reutilizando `kaos.core.chunking`.
